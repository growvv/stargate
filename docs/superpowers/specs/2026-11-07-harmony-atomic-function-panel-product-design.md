### 0.4 文档效力：方向性稿，非最终设计（用户 2026-11-07 澄清）

> **本 Spec 是产品形态与方向的阶段性定义，不是 UI / 推荐 / 分类的最终设计。**
>
> - **待 iOS 分析后定稿的范围**：UI 视觉与风格（含 §5 的②毛玻璃/渐变、色值、材质、圆角、字号、暗色模式）、推荐机制（含 §6.2 的评分公式、冷启动先验、时段/场景/序列权重、类目打散策略）、分类划分方法（类目集合、命名、归属规则、排序方式），以及更广义的「尽量与 iOS 对齐」的信息组织与交互范式。这些当前都是**大致方向**，须以 iOS 资源库 / App Library / Siri 建议 / Spotlight 的实际实现分析为依据重新校准。
> - **不因 iOS 分析而重开的价值判断**（用户已明确拍板，属硬约束）：建议区**完全自动、不允许手动干预**、收藏不钉入建议区；失败**不回退 App 首页、运行时不做多路由降级**、失败即明确报告；「换方案」只在工程/预研层。这三条是产品立场，不是视觉或算法草稿。
> - **结构形态**（卡片优先、4×4、分类/全量/搜索三者第一期都要、长按交给系统桌面菜单）为已确认的工程前提；若 iOS 分析结论要求调整**实现载体**，应另走 spec 修订，不在实现期悄悄改动。
> - **流程**：iOS 分析（含 iOS 模拟器/虚拟机范式研究、必要时 REA 静态逆向）完成后，产出「iOS 对齐设计」作为 §5 / §6.2 / 分类体系的定稿依据；定稿前，实现计划中涉及视觉细节与推荐/分类算法的取值应视为**占位默认值**，可被定稿替换。
>
> 与预研技术文档的关系见本节首部说明；本澄清不修改技术预研 Spec 与预研收尾计划。

> **Stage −1 定稿状态（2026-11-07 / `/goal` 自主执行）**：上述「待 iOS 分析后定稿」的范围已由 `docs/research/ios-paradigm-reverse.md`（取证）+ `…ios-aligned-design.md`（四组 `IOS_*_SPEC` 三栏定稿）完成。对齐层级为**范式对齐**，每条标注 [S]/[I] 依据层级。§5 / §6.2 / 分类体系 / §6.1 拼音已回填定稿取值；**本节三条硬约束原文未改**，技术预研 Spec 与预研收尾计划正文未改。B3 用户终审依 `/goal`「遇到选择自行决策、不要问我」由执行时代为终审（见 SDD ledger `Stage -1: Ruling`），取值均标注为可替换近似。

## 1. 形态与入口（P1）

### 1.1 主形态
桌面 **4×4 服务卡片**（Form Kit / ArkTS Card），毛玻璃/渐变视觉。**产品侧不提供独立 App 主界面** —— 用户与产品的全部接触面就是桌面卡片，以及从卡片点击拉起的两个页面。

> **入口可达性待实证（§0.9 B1′ 拍板）**：「不暴露 Launcher 主 UI 入口」与「用户自行把卡片添加到桌面」存在张力。此点**并入开发计划 Task 0 第 4 项探针 `CARD_ADD_PATH` 真机验证后定**，不预设；若「无 Launcher 入口的 HAP 无法从桌面卡片列表添加」，再回到「允许最小 Launcher 引导页（点开只显示如何添加卡片，非产品主界面）」或「完全不暴露入口、仅开发期 `hdc install`」二选一。**无论哪种，产品主界面都不做。**

### 1.2 工程事实（不是产品倒退）
服务卡片的提供方仍是一个 **HAP**，内含 `FormExtensionAbility`（`onAddForm` / `onFormEvent` / `onUpdateForm`）；卡片由独立渲染进程渲染 `widgets.abc`。因此「不需要 App」的准确含义是：**用户感知上没有一个可打开的 App 主页**，而非「不需要 HAP 包」。该 HAP 只承载卡片提供方与两个拉起页，不暴露 Launcher 主 UI 入口。

### 1.3 入口路径
```
用户添加卡片到桌面 → 卡片常驻可见
  ├ 点建议图标 ──────────────→ 直达目标 App 原子功能
  ├ 点分类 chip ─────────────→ 分类功能页（点击功能 → 直达）
  ├ 点角落「⋯ 更多」────────→ 全量列表页（搜索/点选 → 直达）
  └ 长按卡片 ───────────────→ 系统桌面菜单（配置/移除/调整大小）
```

### 1.4 平台边界（已查证）
- 卡片只支持 `onClick` / `postCardAction` / `FormLink` 跳转；官方设计指南明确「卡片内请勿定义复杂交互，通过点击直达服务；**切勿在卡片内使用长按、多指操作**」。
- 卡片事件子集只有**点击事件 + 挂载卸载/生命周期**，无长按、拖拽、手势类事件；组件为 ArkUI 子集（Blank / Button / Image / Text / Column / Row / Stack / GridRow / List / RelativeContainer 等）。
- 禁用 `@State` / `@Link`、自定义组件、`Navigation`、共享包、native、网络/文件系统、`setTimeout` 等超时任务；左右滑动需避开桌面手势冲突。
- 卡片与提供方是独立进程，数据经 `formBindingData` / `@LocalStorageProp` 传递，须由提供方 `updateForm` 推送刷新（定时/定点/主动）。
- 因此**复杂交互全部下沉到点击拉起的页面**，卡片本身保持「轻量交互、点击直达」。
- `FormMenu`（since 12）是「把卡片添加到桌面」的菜单组件，**不是**卡片内长按编辑能力，不得误用。

### 1.5 延伸形态（非第一期）
桌面快捷方式（Shortcuts）作为备选入口；**收藏 / 手动添加自定义快捷入口**（用户 2026-11-07 拍板移出第一期，见 §2.3）；若后续发现某些功能卡片确实无法支持，再评估**改用独立 App 形态**（这是产品形态的重新选型，与 §4.3 禁止的「跳转失败回退 App 首页」不是同一概念），并按该路径升级设计。

## 2. 信息架构（P2）

### 2.1 三层结构
卡片（展示 + 一点即走）→ 拉起页（分类 / 全量）→ 目标 App 原子功能（外部）。

### 2.2 卡片上的信息分区（4×4 内）
| 区块 | 内容 | 排序规则 | 可否手动干预 |
|---|---|---|---|
| **建议区** | 最多 8 个高频功能图标 + 名称；**首版能力库只收已验证条目（A3/§0.9 B2′），不足 8 格按实际数量显示，不凑数、不填未验证条目** | 推荐引擎完全自动 | **否** |
| **分类 chips** | **定稿类目集合（`IOS_CATEGORY_SPEC`）**：`支付 / 购物 / 出行 / 社交 / 生活 / 娱乐 / 健康运动 / 工具效率 / 其他` + 数量；离线预置归属、用户不可增删改类目 | 用户可重排类目顺序 / 类目内条目顺序（默认预置序） | 是（在配置页改，**不在卡片上拖拽**） |
| **「⋯ 更多」** | 角落常驻入口 | 固定位置 | 否 |
| **情境提示** | 底部一行轻量文字（如「上午好 · 通勤推荐打车」） | 推荐引擎按时段生成 | 否 |

### 2.3 关键决策落地
- **建议区完全自动**：不允许置顶/手动干预。与预研 Spec 的 `pinnedBoost` 差异见 §7 产品层覆盖。
- **收藏 / 手动添加自定义快捷入口：不属第一期（用户 2026-11-07 拍板）**。原始需求中的这两项明确移出第一期，不设收藏区、不提供手动添加自定义入口；§2.2 信息架构因此只有「建议区 / 分类 chips / 更多 / 情境提示」四块。它们与「改用独立 App 形态」同列**延伸形态（非第一期）**，见 §1.5。配置页第一期只保留**分类排序 + 能力库替换入口**（B2 去掉推荐开关、B3′ 不做分类增删改）；`CatalogEditor.setPinned` 与收藏相关能力从第一期计划中移除。
- **多样性约束（`IOS_RANKING_SPEC`）**：建议位（最多 8 格）按类目打散，**同一类目最多 2 条**，避免全是支付类霸屏；候选不足时按实际数量显示、不补位。
- **冷启动**：无使用记录时按时段先验（早晨出行、午间支付、晚间购物，走 `hourAffinity`）+ 分类默认序，**最多 8 格、不足按实际数量、不凑数**（§0.9 B2′），随用量收敛到个人习惯。
- **分类与全量浏览第一期保留**：分类 chips 点进分类页；「更多」点进全量列表页。

### 2.4 数据来源（沿用预研 Spec，不重述技术）
`CapabilityRegistry` 的 `AtomicFunction`（shortcut > linkFeature > scheme > 逆向补全）；用量事件仅记「面板内点击直达」，本地持久化。

## 3. 页面清单与导航（P3）

### 3.1 页面集合（无 Tab、无独立 App 主界面）
| # | 页面/界面 | 承载 | 进入 | 返回 |
|---|---|---|---|---|
| ① | **桌面卡片 4×4** | 建议区 + 分类 chips + 「更多」+ 情境提示 | 用户添加到桌面（**添加路径待 Task 0 `CARD_ADD_PATH` 实证，§0.9 B1′**） | —（常驻） |
| ② | **分类功能页** | 单个分类的全部功能列表 + 分类内搜索 | 点分类 chip | 左上「‹ 返回」/ 侧滑返回 |
| ③ | **全量列表页** | 搜索框 + 拼音 A–Z 分组全部功能 + 右侧索引条 | 点「⋯ 更多」 | 左上「‹ 返回」/ 上滑关闭 |
| ④ | **配置页**（条件性，§0.9 B3′） | **第一期最小配置：分类排序 + 能力库替换入口**；无收藏 / 手动添加 / 推荐开关 / 用量；**B3′ 重评估已完成（`IOS_CATEGORY_SPEC` C2：系统预置类目、用户不可增删改）→ 分类增删改不做、页面维持最小配置** | 系统桌面长按菜单的「编辑卡片」（若 Task 0 证实无该入口则走首次添加引导） | 返回卡片 |

### 3.2 导航模型
- 卡片是**唯一常驻入口**；②③ 是临时拉起的页面，用完即走，不留栈、不做 Tab。
- 从卡片点击任意功能 → **不经过中间确认**，直接直达；失败按 §4.3 处理。
- ②③ 是**同一个 HAP 内的 UIAbility 页面**（不是另一个 App），产品上不视为「打开 App」。
- ④ 配置页的存在取决于桌面长按菜单是否提供可拉起自定义配置页的入口 —— **需真机验证**；若系统菜单不提供，则配置能力降级为「**首次添加卡片时的引导配置**」，并在本文档标注。（此处「降级」指**配置入口的产品方案退让**，与 §4.3 禁止的「跳转运行时降级」不是同一概念。）

### 3.3 与原设计的差异（如实记录）
原「下拉进入搜索页 + 首页分类网格」是独立 App 时代的方案；卡片形态下**下拉手势不可用**，因此：
- 搜索 → 改为「更多 → 全量列表页顶部的搜索框」；
- 分类网格 → 改为「卡片上的分类 chips → 分类页」；
- 拼音 A–Z 全量列表 → 移到全量列表页。

决策的**意图**（分类 + 全量浏览 + 搜索都在）保留，**载体**变更。

## 4. 交互模型（P4）

### 4.1 交互集合
| 动作 | 位置 | 行为 |
|---|---|---|
| **单击建议图标** | 卡片 | 立即直达原子功能，无二次确认（核心「一点即走」） |
| **单击分类 chip** | 卡片 | 拉起分类功能页 |
| **单击「⋯ 更多」** | 卡片角落 | 拉起全量列表页 |
| **单击功能项** | 分类页 / 全量列表页 | 立即直达；不清空搜索状态，便于连续操作 |
| **输入搜索** | 全量列表页顶部 | 实时过滤（按功能名、App 名、分类名匹配） |
| **点字母索引 / 滑动列表** | 全量列表页右侧 | 跳转到对应拼音分组；列表可惯性滑动浏览 |
| **上滑 / 点「‹ 返回」** | 拉起页 | 关闭，回到卡片 |
| **长按功能图标** | 卡片 | **不实现自定义逻辑**（官方禁止卡片内长按） |
| **长按卡片本身** | 桌面 | 交给系统桌面菜单（配置/移除/调整大小） |
| **拖拽** | 卡片 | **不支持**；排序在配置页内完成 |
| **编辑态** | 配置页 | **分类排序 + 能力库替换入口**（第一期最小配置，B3′ 不做分类增删改）；**无收藏、无手动添加自定义入口、无推荐开关、无用量查看/清空** |

### 4.2 拼音排序口径
全量列表按功能名**拼音首字母 A–Z 分组**（A 爱奇艺 / B 百度地图 / D 打车 / F 付款码…），右侧 A–Z 索引条；**定稿口径（`IOS_PINYIN_SPEC`）**：离线常用汉字→首字母表、多音字取常用读音、中文归对应字母组，数字/emoji/符号/空串/未覆盖汉字归 **`#` 杂项桶**（置末），空数据显示空态不崩溃。

### 4.3 反馈与失败处理（已确认修订）
| 情况 | 行为 |
|---|---|
| 直达成功 | 卡片/页面保持不动，无额外反馈（不打断） |
| 直达失败（无响应 / 路由失效 / App 未安装） | **明确失败提示**：「『付款码』暂无可用直达入口」+ 该功能图标标记为失效（小圆点）；**不打开 App 首页、不尝试其他路由、不弹模态阻断** |
| 入口失效的修复 | **工程/预研层**：版本指纹比对 → 重扫 skills/shortcut → REA 逆向 / xpanda·dayu 反编译找新路由 → **替换本地能力库配置文件（§0.7 D5）**；**用户点击时不做自动切换** |
| 首次添加 / 无能力数据 | 引导态「添加你常用的功能」+「配置」按钮 |

「换方案」的准确含义：**只在工程/预研层换方案，运行时不做降级**。理由：用户点的是「付款码」，结果给个 App 首页等于没做到直达，违背核心定位；应如实报告失败，由工程侧修复入口。

### 4.4 交互原则
全部交互遵循官方「卡片轻量交互、点击直达」原则，卡片内不放流程型操作；拉起页为普通 UIAbility 页面，不受卡片组件/手势子集限制。

## 5. 视觉系统（P5）

> **状态：已定稿（Stage −1 / `IOS_VISUAL_SPEC`，2026-11-07）。** 本节取值已按 `…ios-aligned-design.md` §3 定稿，依据为 Apple HIG「Materials / Dark Mode / Color / Index lists」+ WWDC/公开资料可观察结论；对齐层级为**范式对齐、非机制复刻、不像素级比对**，每条标注 [S]/[I]。数值为鸿蒙侧实现取值，不宣称是 iOS 数值。②毛玻璃/渐变基调保留，`backdrop-filter` 不可用时按 §5.3 退化。「不做像素级复刻、不做越权模仿」原则不变。

### 5.1 基调
**② 毛玻璃 / 渐变**（已确认）：柔和彩色渐变背景 + 半透明毛玻璃卡片，iOS 控制中心/壁纸感。

| **卡片材质** | 亮色 `#ffffff30` + `backdrop-filter: blur(13px)` + `border: 1px solid #ffffff55`；模糊不可用时退化 `#ffffff4d` 半透纯色、`blur=''`（渐变保留）；建议图标容器 `#ffffff55` 再叠一层 |

| **文字** | 主文字 `#ffffff`、次文字 `#ffffffd9`（暗色 `#ffffffb3`）；字号（fp）：卡片标题 16、功能名 12、情境提示 10、chip 12、全量列表项 14；材质上统一**浅色高对比**，禁止深灰文字 |
| **图标** | **引用第三方 App 图标/名称**（§0.7 D2 拍板，自用范围取舍）：彩色圆角容器内放目标 App 图标 + 功能名；分类 chips 用半透明胶囊；可带来源色做弱区分。**此取舍绑定 D1「内部自用/不上架」；若将来改为上架目标，必须换成自绘 glyph 表**（见 §6.4） |
| **排版** | 大标题 + 小字副标题、大写小标签（`建议 · 自动排序`）、克制留白、建议区最多 8 格等距（不足留白不占位符凑数） |

| **动效** | 卡片内**不做动效 / 长按 / 拖拽 / 多指**（官方「请勿定义复杂交互」）；仅 `postCardAction` 点击；禁用 `setTimeout`；拉起页系统标准转场 |
| **状态标记** | 失效功能右下角小圆点（低饱和红/灰）；首次添加引导态用半透明占位卡片 +「配置」按钮 |

### 5.3 平台约束的如实标注
- 卡片侧组件为 ArkUI 子集，禁用自定义组件、`@State`/`@Link`、`Navigation`、网络/文件系统；拉起页无此限制。
- **`backdrop-filter` 在卡片渲染进程是否生效由 Task 0 `BLUR_SUPPORTED` 探针定**；不支持则 `ThemeTokens.build(false, dark)` 退化「半透明纯色 `#ffffff4d` + 渐变背景、`blur=''`」，仍保持②基调，不改用①iOS 原生克制（`IOS_VISUAL_SPEC` V1）。

### 5.4 与 iOS 的对齐方式
对齐的是 **iOS 控制中心/壁纸的材质感 + 资源库/Spotlight 的信息组织与轻量交互范式**，不是像素级复刻 iOS 系统 UI，也不做越权模仿。

> **执行状态**：Stage −1 已完成，四组 `IOS_*_SPEC` 见 `…ios-aligned-design.md`；B3 终审依 `/goal` 自主执行代为完成（SDD ledger Ruling），取值标注为可替换近似。

## 6. 数据来源、状态、验证与交付物（P6）

### 6.1 数据来源与状态
- **能力清单**：沿用预研 Spec 的 `AtomicFunction`（shortcut > linkFeature > scheme > 逆向补全），`CapabilityRegistry` + 版本指纹；工程层通过重扫 / REA 逆向 / xpanda·dayu 反编译更新，**不下发运行时降级**。**分发方式（§0.7 D5 拍板）**：能力库是**本地可替换配置文件**，开发期可用 `hdc push` 等直接替换，**不必重新打包 HAP、不建服务端、不上云**；首批只收已实测可用条目（A3）。**首版覆盖口径（§0.9 B2′）**：建议区 / 分类页 / 全量列表**共用这一批已验证条目**，条目少也接受，全部可直达、无失效项；建议区不足 8 格按实际数量显示。
- **用量事件**：仅记「面板内点击直达」，本地持久化；日/月双窗口 + 时段分桶，纯本地计算，不上云。**用户控制（§0.7 D4 拍板）**：用量只是排序内部输入，**不可见、不可清空**，不进配置页、不提供清空入口。
- **拼音分组（已定稿，`IOS_PINYIN_SPEC` / §0.7 D3）**：离线常用汉字→首字母表、多音字取常用读音（重庆→C、银行→Y…）、中文归 A–Z 对应组，数字/emoji/符号/空串/未覆盖汉字归 `#` 桶（置末），空数据空态；映射不引入第三方依赖。
- **界面状态**：正常 / 冷启动（时段先验、**最多 8 格、不足按实际、不凑数**：B2′）/ 首次添加无数据（引导态）/ 功能失效（小圆点 + 明确失败提示）/ 搜索空结果 / 暗色模式。（**无「推荐关闭态」**：§0.7 B2 去掉开关）

### 6.2 推荐引擎（已定稿，`IOS_RANKING_SPEC`）
**定稿公式（`…ios-aligned-design.md` §2，范式对齐近似，非 iOS 机制数值）**：

```
score(f, now) =
    0.30 * norm(dayCount)      + 0.20 * norm(monthCount)
  + 0.18 * exp(-Δt / τ)         // Δt = now - lastUsedAt, τ = 36h
  + 0.12 * hourAffinity(f, nowHour)
  + 0.08 * sceneAffinity(f, scene)   // 首版常量 0，保留接口
  + 0.07 * seqBoost(f, recentSequence())
  + 0.05 * confidence
```

- `norm(x)` 为相对候选集的 `x / maxX`（maxX=0 → 0）；无历史 `lastUsedAt` 时衰减项取 0；同分按 `id` 字典序保证可复现。
- **打散**：按分数降序取前 `n=8`，但任一 `category` 已选满 2 条则跳过；**不足 8 格返回实际条数，绝不补位**（§0.9 B2′）。
- **无** `isPinned` / `pinnedBoost` / 收藏因子 / 用户可关闭的推荐开关；`UsageSnapshot` 不含 `isPinned`。
- **冷启动**：无历史时由 `hourAffinity` 时段先验给不同类目基数，随用量收敛。
- **刷新时序（§0.6 A2 拍板）**：点击即重排 + 定时兜底——每次点击直达记用量后立即 `formProvider.updateForm` 重排，再叠短周期定时刷新兜底。
- **取证**：WWDC18 Session 211 直接引文「the system will look at the time, location, and other signals … the time of day and the day of the week … a significant location」+ Apple 开发者文档《Increasing App Usage with Suggestions Based on User Activities》。机制级权重为系统私有、不在取证范围，用可解释线性加权近似并写死为常量。
- **建议区完全自动、不允许手动干预**（产品层覆盖，见 §7）为用户明确拍板的硬约束，**不随算法定稿改变**。

### 6.3 验证方式（本机 HarmonyOS 7.0 / API 26 真机 `5KPBB25927200695`）

## 7. 产品层覆盖技术层的差异（重要）

本 Spec 与预研 Spec 有三处**有意的产品层覆盖**，实现时以本 Spec 为准，但预研文档不改：

| # | 预研 Spec | 本产品 Spec | 理由 |
|---|---|---|---|
| 1 | `pinnedBoost`：收藏/置顶影响推荐排序 | **收藏与手动添加整体移出第一期**（§2.3 拍板）；建议区完全自动、不允许手动干预 | 最贴近 iOS Siri 建议；用户要的是智能推荐而非自定义快捷栏 |
| 2 | 多路由逐级降级 → 最终 `openLink` 回退 App 首页 | **不回退 App 首页**；失败即明确报告「暂无可用直达入口」 | 打开首页等于没做到直达，违背核心定位 |
| 3 | `routes[]` 运行时多路由依次尝试 | **运行时单条最可靠路由，不做降级**；「换方案」只在工程/预研层（重扫/逆向找新路由/更新能力库） | 用户要的是如实报告失败并由工程侧修复，而非运行时兜底 |

预研 Spec 的**版本指纹 + 自动重扫自愈**机制保留，但作用点移到工程/预研层与**本地能力库配置文件替换流程**（§0.7 D5，不要求重新打包 HAP），不参与用户点击时的运行时链路。

## 8. 典型使用方式（场景）

1. **日常高频**：用户在桌面看到 4×4 卡片 → 点「付款码」→ 直达支付宝付款码 → 用完返回桌面，卡片仍在。全程无需打开任何 App 主页。
2. **按分类找**：点「出行」chip → 分类功能页列出打车/路线规划/12306 → 点「打车」→ 直达高德打车页。
3. **找不常用的**：点角落「⋯ 更多」→ 全量列表页 → 顶部搜索框输入「鉴别」，或滑到拼音 D 分组 / 点右侧索引 D → 点「得物 · 鉴别」→ 直达。
4. **配置**：长按桌面卡片 → 系统菜单「编辑卡片」→ 第一期最小配置页里改分类顺序、替换本地能力库文件（**无收藏、无手动添加、无推荐开关、无用量、无分类增删改**：§0.7 B2 / §0.9 B3′；若系统菜单不提供该入口，则在首次添加卡片时引导配置）。B3′ 重评估已完成：分类是系统预置自动归类（`IOS_CATEGORY_SPEC`），故分类增删改不做、页面维持最小配置。
5. **入口失效**：点某功能 → 明确提示「暂无可用直达入口」+ 图标小圆点 → 工程侧通过版本指纹重扫/逆向补新路由，**替换本地能力库配置文件**（§0.7 D5，不必重新打包 HAP）。
